COMMON RULES FOR EVERY LANE (MarketEdge overnight build). Work unattended; never ask the user anything. Pick the option that best fits the docs and list it under "Decisions" in your final report.
- Setup: your worktree starts from `main` (wrong). First run `git fetch && git checkout -B <your-branch> origin/final`. Then `cd apps/web && pnpm i` (and `cd apps/extension && pnpm i` if you touch it).
- Never push to or merge into `final`; the lead merges your branch. Commit on your branch, one commit per task, message `T-xx: title` + trailer line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Push your branch to origin at the end (`git push -u origin <branch>`).
- Read first: CLAUDE.md, docs/README.md, docs/OVERNIGHT.md §0 (ground rules), then your lane's docs. Product rules: no personalized picks from users' own bets/positions; no auto-trading; footer disclaimer "Market analytics, not financial advice. Based on past results. 18+." on every page and extension popup; never the words pick/lock/guaranteed/sure thing/can't lose in user-facing text; display language from docs/06 (percentages, "Pays Nx", plain words; "Worth it" never as a badge).
- UI work: load the Impeccable skill (Skill tool, `impeccable:impeccable`) before building UI and follow the approved "Chosen" design: docs/06-ui.md and docs/design/. Dark theme first, emerald #10b981, rounded-xl, borders 1px #1a2520. Verify UI in a real browser (Playwright screenshots) at 390px and 1440px.
- Ports: use ONLY your assigned ports: `PORT=<dev> pnpm dev`, `PW_PORT=<e2e> pnpm e2e`. Other lanes run concurrently.
- Don't rewrite engine/ or pipeline/. Never delete/skip/weaken a test. Never weaken a security control. Never commit secrets; every key goes in `.env.example` with an empty value — append yours in a block headed `# --- <Lane> ---` (create the file at repo root if missing).
- Owner values (support email, operator names, state, domain, address, refund choice, payment links) come from `config/site.json`; when empty render a clear placeholder like `[[SUPPORT_EMAIL]]`. Never invent them.
- Setup instructions for the owner: do NOT edit SETUP.md (the lead composes it). Write yours to `docs/setup-notes/<lane>.md`: every account, every env var, where to paste it, in order.
- Done = `cd apps/web && pnpm typecheck && pnpm test` green, plus `pnpm e2e` green for flows you touched (and lane-specific checks). Keep existing tests passing (DEMO_MODE=true must still work with no keys).
- Ponytail: smallest code that works, reuse what exists (lib/, components/kit), no speculative abstraction. But don't skip validation, error handling, security, accessibility.
- Final report under 300 words: branch, commits, what works, what's behind a flag/needs an owner value, known issues, Decisions.
